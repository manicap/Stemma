# Řízený reálný pilot roje – 18. 11. 2026

Tato větev připravuje jediný omezený test autonomního řešení skutečné chyby v již existujícím rozhraní Stemma. Příprava není spuštění: modelové úlohy mohou vzniknout až po samostatném explicitním startu uživatelem.

## Výchozí stav

Základ je commit 5820ee48978817bfee1106f03ede9a54ded18ce9 (aplikační RC 0.2 a projektová značka reasoning policy). Historické .swarm-demo fixtures do pilotu nepatří. Původní main, RC větve, demo, worktrees a jejich evidence se nemění. Bez push, merge do main nebo nasazení.

## Jediný úkol

Pokud uživatel před startem neurčí přesnou chybu, Lead smí vybrat nejvýše jednu malou, reprodukovatelnou chybu existujícího UI seznamu/detailu/vyhledávání osob nebo přihlašování, doloženou současným chováním a platnou specifikací. Nejde o volnou tvorbu nových doménových funkcí. Pokud takovou chybu nedoloží, vrátí blocked s důkazy a dál se nepokouší generovat náhradní funkce.

Před opravou musí existovat konkrétní reprodukce či smysluplný selhávající regresní scénář. Oprava má zachovat architekturu, HTMX/SSR, stávající oprávnění a ACP-012. Scope: nejmenší nutné šablony, statické UI soubory, relevantní regresní testy a dokumentace skutečné změny. Databázový model, migrace, přístupové politiky, controller a limity jsou mimo scope. Pokud reprodukce vyžaduje změnu mimo tento rámec, úkol zůstává blocked.

## Akceptace

1. Jedna skutečná chyba, konkrétní očekávané/pozorované chování a reprodukce před opravou.
2. Regresní scénář projde po opravě; původní relevantní testy zůstanou zachované.
3. Skutečná browser kontrola změněného uživatelského toku, včetně relevantního odmítnutí přístupu; pouze syntetická data a izolované úložiště.
4. Nezávislé QA a security schválí přesný kandidátní SHA.
5. Integrace zachová kandidátní ancestry, povolené cesty a skutečné ověřovací důkazy. Stabilní ref posouvá pouze controller.
6. Uložený výsledek uvede integrovaný SHA, rozsah, čas, pozorované tokeny, stav kontrol a omezení. Pilot neprohlašuje celé Stemma za dokončené či připravené do produkce.

## Rozpočet a zastavení

Jedna iterace, nejvýše osm nativních úloh včetně Leada a revizí, jeden souběžný pracovník, maximálně dva pokusy na úkol (první a jedna oprava), dvě hodiny, milion pozorovaných tokenů celkem a 300 tisíc na běh. Provider limit vyžaduje ruční obnovu. Telemetrie a rušení mají zpoždění; tento rozpočet není providerem vynucený limit ani převod na procenta předplatného.

Po první iteraci se nepokračuje v dalším vývoji. Při úspěchu je rozhodující integrační report a položka v history; controller pak může zobrazit limit jediné iterace, což není tvrzení o dokončení produktu.
